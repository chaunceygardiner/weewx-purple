# Translating the sample report

[weewx-purple manual](https://chaunceygardiner.github.io/weewx-purple/) · [weewx-purple on GitHub](https://github.com/chaunceygardiner/weewx-purple) · [Report an issue](https://github.com/chaunceygardiner/weewx-purple/issues)

---

As of 6.0 the sample report is translatable, entirely through WeeWX's own
mechanisms — lang files and `[Texts]`/`$gettext` — the same machinery as
WeeWX's bundled Seasons skin.  There are no invented conventions to learn:
if you have translated a WeeWX skin before, this works the same way.

![The sample report in German](https://raw.githubusercontent.com/chaunceygardiner/weewx-purple/master/PurpleReport-de.png)

*Shown on 09/11/2020, the day wildfire smoke turned the Bay Area sky
orange.  Most days are green; this is the one the colors are for.*

## How it works

Every string the page renders is a **gettext-style `[Texts]` key: the
English string is the key**.  A report falls back to English one string at
a time, so a partial translation is fine — a missing key never breaks the
page, it just renders in English.

The words come from three core-standard sources, all supplied by
`lang/<lang>.conf`:

| What | Where it is translated |
|---|---|
| The heading and browser title (`{location} Air Quality` — keep the `{location}` slot, and put it where your language wants it), "Unavailable", the card headings, the four stat-tile labels, the six AQI category names and their six health sentences, the Day/Week/Month/Year tabs | `[Texts]` |
| Observation labels — the particulate readouts and every plot title | `[Labels]` `[[Generic]]` (`pm2_5_aqi`, `pm1_0`, `pm2_5`, `pm10_0`) |
| Unit labels — the " AQI" suffix on values, " RGB" | not from a lang file: `purple.py` registers them |

The category names and health sentences are the bulk of the file, and the
part worth the most care: they are what turns a number into something a
reader can act on.

The lang files also localize the year plot's date axis
(`[ImageGenerator]` `[[year_images]]` `x_label_format`: day-month instead
of the US month/day).  Since the plots are PNG images, a language
change appears as the images regenerate — the day plots on the next report
cycle, the year plot within a day.

## Translating

**German, French, Dutch and Spanish ship with the skin** — `lang/de.conf`,
`fr.conf`, `nl.conf` and `es.conf` are complete translations of the
dictionary, each kept complete by a test, so new strings cannot ship
untranslated.  The plot-period tabs are identical to the translations of
WeeWX's own Seasons skin (a test pins them).  Corrections are welcome —
[file an issue](https://github.com/chaunceygardiner/weewx-purple/issues).
To use one:

```ini
[StdReport]
    [[PurpleReport]]
        lang = de                # or fr, nl, or es
```

For any other language, the skin ships its reference dictionary at
`skins/purple/lang/en.conf` — every string the page renders, and nothing
else (a test keeps it exact in both directions).  To add a language:

1. Copy `en.conf` to `<code>.conf` in the same `lang` directory (e.g.
   `it.conf`) and translate the values — the keys stay English.  Keep
   every key, including `x_label_format`, which carries your language's
   date order; a test requires every lang file to set it.
2. Point the report at it in `weewx.conf`:

```ini
[StdReport]
    [[PurpleReport]]
        lang = it
```

Further languages are welcome as contributions — a lang file is a
self-contained, no-code contribution.

## One place for the whole station: Defaults

Anything under `[StdReport]` `[[Defaults]]` in `weewx.conf` is merged by
WeeWX into **every** report:

```ini
[StdReport]
    [[Defaults]]
        lang = de                # every skin that ships German goes German
```

`lang = de` selects each skin's own `lang/de.conf` — Seasons, this page and
any other skin that ships German switch together.  A skin with no German
simply stays English: a missing lang file is a logged no-op, never an
error.

`[[Defaults]]` (or the report's own section) is also the durable home for
local overrides: `weectl extension install` overwrites `skins/purple/` —
including its lang files — on every upgrade, while `[[[Texts]]]`/
`[[[Labels]]]` entries in `weewx.conf` survive and are merged over them.

## The dictionary

The reference dictionary.  `skins/purple/lang/en.conf` in the installed
extension is always the authoritative copy for your version — this listing
is here so you can see the shape of it without installing:

```ini
[Labels]

    [[Generic]]
        pm2_5_aqi = Air Quality Index
        pm1_0     = PM1.0
        pm2_5     = PM2.5
        pm10_0    = PM10

[ImageGenerator]

    [[year_images]]
        x_label_format = %m/%d

[Texts]

    # The page heading and the browser title.  {location} is [Station]
    # location from weewx.conf; translate the whole phrase, preposition
    # and all, since {location} may sit anywhere in it.  The second form
    # is the fallback for a station that has set no location.
    "{location} Air Quality" = "{location} Air Quality"
    "Air Quality" = "Air Quality"
    "Unavailable" = "Unavailable"

    "Right now" = "Right now"
    "The last 24 hours, hour by hour" = "The last 24 hours, hour by hour"
    "History" = "History"

    "Today's peak" = "Today's peak"
    "Today's average" = "Today's average"
    "Today's low" = "Today's low"
    "Hours above Good" = "Hours above Good"
    "in the last 24 hours" = "in the last 24 hours"

    "Good" = "Good"
    "Moderate" = "Moderate"
    "Unhealthy for Sensitive Groups" = "Unhealthy for Sensitive Groups"
    "Unhealthy" = "Unhealthy"
    "Very Unhealthy" = "Very Unhealthy"
    "Hazardous" = "Hazardous"

    # One health sentence per category, in the same order.  These are the
    # US EPA's own AirNow category descriptions -- the longest strings in
    # the file, and the ones most worth getting right.  In en.conf each of
    # these values is its own key, exactly as above; only the right-hand
    # side is elided here, to keep the lines readable.
    "Air quality is satisfactory, and air pollution poses little or no risk." = ...
    "Acceptable.  Unusually sensitive people should consider limiting prolonged outdoor exertion." = ...
    "Sensitive groups may experience health effects.  The general public is less likely to be affected." = ...
    "Some members of the general public may experience health effects." = ...
    "Health alert: the risk of health effects is increased for everyone." = ...
    "Health warning of emergency conditions: everyone is more likely to be affected." = ...

    "Day" = "Day"
    "Week" = "Week"
    "Month" = "Month"
    "Year" = "Year"
```

`Day`, `Week`, `Month`, `Year` and `History` are shared with WeeWX's own
Seasons skin, and the shipped translations are Seasons' — a test pins them,
so a page that sits beside a Seasons report uses the same words for the
same things.
